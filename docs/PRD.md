# 다음길 (Daeumgil) — PRD v1.0.0

문서 상태: 초기 개발 명세. Android 우선. 기본 언어 한국어.

슬로건: 지금 가는 길에서, 목적지까지.

개발 방식: GitHub Issue → 기능 브랜치 → Pull Request → 빌드·테스트 → 사용자 승인 → 병합.

사용자가 제공한 PRD를 저장소 개발 기준으로 정리한 문서입니다. API 요금·한도·지원 지역은 공급자의 최신 문서 및 실제 응답으로 다시 검증해야 하며, 제품 요구사항만으로 확정하지 않습니다.

## 1. 제품 목표와 원칙

검색, 버튼, 목록으로 현재 이동 상태와 목적지를 선택하면 다음 행동을 안내합니다. 일반 출발지 경로 탐색뿐 아니라 이미 탑승한 버스·지하철을 계속 이용할 수 있는 후보를 검토합니다.

- MVP: 수도권 지하철·버스 중심. 지원 가능한 구간만 명확히 표시합니다.
- 확장: 전국 대중교통, 복합 환승, 실시간 정보.
- 계정과 위치 권한을 강제하지 않습니다.
- 방향이나 차량 정차 정보를 확인하지 못하면 하차 지시를 생성하지 않습니다.
- 현재 차량 유지가 항상 최적이라고 가정하지 않습니다.
- GPS만으로 열차 내부의 정확한 현재 역을 판단하지 않습니다.
- 확인되지 않은 실시간 상태와 예상 시간을 확정적으로 표시하지 않습니다.
- 장소·노선·역 식별에는 공급자 ID를 사용합니다. 이름만으로 동일 개체를 판단하지 않습니다.

## 2. 사용자 흐름

### 시작 화면

현재 이동 상태, 목적지 검색, 최근 목적지, 즐겨찾기, 저장된 안내 이어하기를 제공합니다. 로그인이나 위치 권한 요청으로 시작을 막지 않습니다. 이전 안내가 없으면 이어하기를 활성화하지 않습니다.

### 현재 이동 상태

| 상태 | 입력 정보 |
| --- | --- |
| 아직 탑승하지 않음 | 역·정류장·장소 선택 |
| 지하철·전철 탑승 중 | 노선, 현재/마지막 통과역, 진행 방향, 필요한 경우 급행·일반, 탑승 확인 |
| 버스 탑승 중 | 지역, 버스 번호, 공급자 노선 ID, 현재/직전 정류장, 방향 |
| 걷는 중 | 주변 역·정류장 또는 직접 장소 검색 |
| 택시·기타 이동 중 | 확인한 위치와 현재 상태; 지원되지 않는 안내는 표시하지 않음 |

같은 버스 번호의 다른 지역·방향·노선은 구분합니다. 노선을 변경하면 기존 방향·정류장 등 종속 선택을 초기화합니다. 모르는 정보는 미확인으로 표시합니다. 지도에서 위치 지정은 후속 확장입니다.

### 목적지

장소명·역명·정류장명·주소 검색, 자동완성, 동명이장소 구분, 선택 표시, 최근 기록 삭제, 즐겨찾기 등록·해제를 지원합니다. ID, 좌표, 공급자 정보를 저장하며, 저장된 즐겨찾기는 오프라인 조회가 가능합니다.

### 경로 목록

최소 소요시간, 최소 환승, 최소 도보, 현재 교통수단 유지 우선으로 후보를 정렬합니다.

카드에는 예상 총 시간·도착시간, 이용 노선, 환승 수, 도보 거리/시간, 현재 교통수단 유지 여부, 데이터 출처·시각·실시간 여부를 표시합니다. 시간의 근거가 없다면 숫자를 만들어 표시하지 않습니다.

### 탑승 상태 기반 탐색

1. 선택 노선·방향·확인 시각·위치를 해석합니다.
2. 해당 운행 패턴에서 다음으로 실제 도달하는 정차 지점을 조회합니다.
3. 이미 지난 지점과 미정차 지점을 하차 후보에서 제외합니다.
4. 가능한 하차 지점별 후속 경로를 검색하고 현재 탑승 구간과 결합합니다.
5. 차량 유지와 조기 하차 후보를 비교합니다.
6. 연결·방향·정차·운행 조건이 검증된 경로만 안내합니다.

급행, 분기, 순환, 막차, 회차, 운행 종료를 표현할 수 있어야 합니다. 순환 노선은 역 ID만으로 앞뒤를 판단하지 않고 방향별 정차 순번과 운행 패턴을 사용합니다. 외부 출발·도착 좌표 검색 결과만으로 현재 탑승 조건이 만족됐다고 간주하지 않습니다.

### 단계별 안내

단계: 도보·탑승·차량 유지·하차·환승·도착. 다음 행동 하나를 가장 크게 표시합니다. 각 단계는 ID, 유형, 출발·목표 위치, 노선·방향, 행동, 근거가 있는 시간, 주의사항, 완료 요건, 완료 상태를 포함합니다.

하단 조작: 완료했어요, 현재 위치 변경, 경로 다시 찾기, 안내 종료. 수동 완료는 중복 처리하지 않습니다. 앱 재실행 시 안내 세션을 복원합니다. 복원된 경로의 시각·운행 조건을 재확인하기 전 최신 안내로 취급하지 않습니다.

### 재탐색

하차역 통과, 다른 노선 탑승, 반대 방향, 환승 실패, 목적지 변경, 운행 중단을 처리합니다. 기존 목적지를 유지하고 현재 상태만 바꿀 수 있습니다. 재탐색 중 기존 안내를 정상 안내처럼 표시하지 않습니다. 새 경로 검증 실패 시 오류와 수정·재시도 조작을 제공합니다.

## 3. UI와 접근성

- 미니멀한 세로 UI, 라이트·다크·시스템 테마.
- 주요 버튼 하단 배치, 최소 48dp 터치 영역, 시스템 바 여백.
- 글자 확대·줄바꿈·스크롤·다양한 화면 크기 지원.
- 색상 외에 노선 텍스트, 스크린리더 레이블, 충분한 대비.
- 다음 행동의 텍스트를 우선하며 지도는 보조 수단.
- 오류 원인과 해결 조작을 함께 표시.

| Home | 현재 상태·목적지·최근·즐겨찾기·안내 이어하기 |

## 4. 기술 설계

기본 스택: Kotlin, Compose, Material 3, MVVM, Coroutines/Flow, DataStore. 필요한 단계에서 Retrofit/Ktor, Room, Location API, Hilt를 도입합니다. 최소 API 26. Gradle 모듈은 초기에는 `app`으로 시작하고 책임별 패키지를 확장한 뒤 필요에 따라 분리합니다.

Presentation: Compose, ViewModel, UI State.

Domain: SearchRoute, ResolveCurrentTransit, RankRoutes, BuildNavigationSteps, RecalculateRoute, AdvanceNavigation 등의 유스케이스와 저장소 계약.

Data: TransitRepository, LocationRepository, FavoritesRepository, NavigationSessionRepository, TransitApiProvider 구현.

### 향후 핵심 데이터 모델

| 모델 | 필드 |
| --- | --- |
| CurrentTransitContext | transportType, providerRouteId, routeName, directionId, lastConfirmedStopId, stopSequence, servicePatternId, vehicleServiceType, confirmationTime, confidenceLevel |
| Destination | providerId, id, name, address, latitude, longitude |
| TransitRoute | routeId, estimatedDuration(선택), transferCount, walkingDistance(선택), segments, sourceProvider, dataTimestamp |
| NavigationSession | sessionId, destination, selectedRoute, currentStepIndex, currentTransitContext, status, updatedAt |
| NavigationStep | stepId, type, instruction, originStopId, targetStopId, routeId, completionRequirement, completionStatus |

위 표는 후속 단계의 계약 초안입니다. 공급자 데이터 검증 전 구현된 모델로 오해하지 않습니다. 복수 공급자 식별자 통합에는 검증된 매핑 테이블을 둡니다.

경로 계산은 RouteProvider, TransitNetworkProvider, CurrentRideResolver, RouteConstraintBuilder, RouteRankingEngine, RouteInstructionBuilder로 책임을 분리합니다.

### API와 보안

경로 탐색, 노선·정차순서, 장소 검색, 실시간 정보를 공급자 인터페이스 뒤에 둡니다. 공급자 계약과 실제 지원 범위를 검증합니다. Mock 데이터는 테스트 전용이며 실제 경로와 혼동되지 않게 합니다.

API 키를 GitHub와 APK에 넣지 않습니다. 필요한 경우 서버 프록시, 호출량 제한, 비용 모니터링을 도입합니다. 캐시 정책은 공급자 약관을 따르며, 위치·개인 이동 기록을 불필요하게 수집하거나 로그에 남기지 않습니다.

## 5. 오류 처리

네트워크 없음·시간 초과·한도 초과·지원 밖 지역·동명이정류장·노선/정류장 불일치·도달 가능한 정류장 없음·방향 부족·경로 없음·갱신 지연·프로세스 종료·권한 거부·잘못된 완료·이미 지난 하차역·실제 운행과 저장된 경로 불일치를 처리합니다.

모르는 실시간 위치나 운행 상태를 확정적으로 표시하지 않습니다. 재탐색 중 기존 단계 진행을 차단하고, 사용자 수정과 복구 경로를 제공합니다.

## 9. MVP 출시 기준과 지표

버튼 기반 상태 입력, 목적지 검색, 실제 데이터 경로 탐색, 탑승 조건 검증, 단계 안내, 수동 진행, 재탐색, 권한 없는 사용, 주요 오류 처리, 핵심 테스트가 모두 완료되어야 합니다.

완전 자동 추적·음성 길찾기·계정·광고·서버 개인 이동 기록 동기화는 MVP 필수가 아닙니다.

QA 지표: 경로 검색 성공률, 잘못된 하차 지시 수, 상태 입력 완료율, 재탐색 성공률, 응답시간, 비정상 종료율, API 호출당 평균 비용. 잘못된 하차 지시는 중대한 결함으로 분류합니다.
